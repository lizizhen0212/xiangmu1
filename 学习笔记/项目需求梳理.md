# 项目需求梳理 · 学习一体化工具

> **来源**：`学习笔记/项目开发（纯手搓部分）.md`（原稿未改动，保留在原处）
> **版本**：v0.1 · 2026-11-24
> **说明**：原稿列了 5 个功能、第 3 节留空。本文保留这 5 项原意，按"重排结构 → 补细节 → 划优先级 → 列待定"梳理。标 **【新增】** 的是原稿没有、我建议补的。

---

## 一、定位

**一句话**：用一个日历把"什么时候学、学什么、学到哪、错在哪"串起来的学习工作台。

- **目标用户**：大学生——有课表、有作业截止时间、有考试刷题需求。原稿 5 个功能几乎全部指向这个人群。
- **要解决的痛点**：原稿原话是"各种学习工具方面的痛点"。把它说具体：日历、待办、番茄钟、刷题分散在 4~5 个 App 里，数据互不相通，每天在它们之间来回切。
- **差异化**：所有模块共享同一个"日期"维度，而不是并排堆功能。

## 二、功能架构：先定地基

原稿的 5 个功能不是平级的。重排后是三层：

| 层 | 模块 | 作用 |
|---|---|---|
| 底座 | A 学习日历 | 日期索引，所有数据按天挂载 |
| 活动 | B 每日日程 · C 事件提醒 · D 番茄钟 · E 刷题 | 产生数据的主要入口 |
| 记录 | F 打印导出 · G 学习统计【新增】 | 把数据变成可看、可带走的东西 |

**关键判断**：如果日历不自带"聚合视图"，这个产品就退化成 5 个功能的拼盘。建议点某一天时，弹出的是那天的全部内容——备忘录 + 日程 + 到期事件 + 番茄时长 + 刷题记录，而不是再跳一个新页面。

## 三、逐模块细化

### A. 学习日历

> 原稿：可联网查看日历，点击对应天数可以写备忘录。

需要定下来的：

- **视图**：月视图（主）→ 周视图 → 日视图（时间轴）
- **"联网"具体指什么**（待定）：节假日 + 调休（中国大陆习惯）？农历？还是仅校历？
- **学期周次**：是否显示"第 12 周"。大学里比日期更好用，建议加。
- **备忘录**：纯文本还是 Markdown？支持图片？（如果你是 Obsidian 用户，可能希望 Markdown）
- **离线**：断网时日历仍能看（缓存节假日数据），联网只影响"更新"

### B. 每日日程表

> 原稿：自带多种日程表模板，可选后做日历调整，要与学习日历联动，可导入课表，一键生成打印文件。

这是原稿信息量最大的一项，拆成 4 件事：

1. **模板**：日计划（时间段列表）/ 周计划（表格）/ 时间块（时间轴）/ 四象限（重要-紧急）。建议第一版只做「时间段列表 + 周计划表格」。
2. **课表导入**（其实是独立子功能）：先要定义「课程」实体——课名、教师、地点、星期几、第几节、**周次范围**、**单双周**。大学的课表几乎必须支持单双周，否则导入后每周都是错的。
3. **导入格式**（待定）：Excel 模板 / 教务系统导出的 Excel 或 HTML / 手动粘贴文本。低成本方案：只支持「下载 Excel 模板 → 填好上传」，格式自己定。
4. **打印**：A4 竖版，日视图或周视图，含日期、时间段、留白书写区、复选框——要能在纸上直接写。

### C. 事件与提醒

> 原稿：设一件事 + 起止时间 → 截止前多节点提醒（半天 / 3 小时 / 1 小时 / 半小时）→ 时间和频率可自定义 → 一键保存，下次默认用。

拆开：

- **事件模型**：标题、类型（作业/考试/会议/其他）、开始时间、截止时间、优先级、关联课程
- **提醒方式**：一组「提前量」（可增删、可排序），另加「某个固定时刻提醒」（如每周日 20:00 提醒规划下周）——两种应该混用
- **记住上次**：建议升级成**可命名的提醒方案**（"作业标准提醒" = 12h / 3h / 1h / 30min）。比"记住上次"更可解释，也能给不同事件类型配不同方案
- **送达渠道是本项目最大的技术分叉**（详见第七节）：只在 App 打开时弹 → 简单但"电脑关着就废"；系统级通知 → 中等；手机推送/邮件/微信 → 需要服务端常驻，成本陡增
- **错过补发**：触发时程序没运行，下次启动要不要补提醒一次？建议补，并标注"已过期"

### D. 番茄学习钟

> 原稿：可自主设立各种倒计时、正计时，自带番茄钟学习功能。

拆开：

- **番茄**：默认 25/5，可改（专注时长、短休、长休、几轮后长休）
- **正计时**：手动开始 / 暂停 / 结束，用于"不知道要多久"的学习
- **与事件绑定**：开一个番茄时选「这次在做什么」（从今日事件里挑）→ 时长自动记到该事件上。这是把 D 接回主线的关键，否则它只是个孤立秒表
- **收尾**：提示音 + 桌面通知；可选全屏 / 勿扰，减少干扰
- 【新增】**统计**：今日/本周专注时长、最长连续天数

### E. 刷题

> 原稿：导入题库、刷题、错题本、错题重做。

拆开：

- **题型**：单选 / 多选 / 判断 / 填空 / 简答（简答无法自动判分，标记为"自评"）
- **题库导入**：Excel / CSV 模板（题干、选项 A~D、答案、解析、章节标签）——格式自己定，先给模板
- **刷题模式**：顺序 / 随机 / 按章节 / 只刷错题 / 模拟考试（限时）
- **错题本**：答错自动收录 + 手动收藏；记错误次数、最近错误时间
- **错题重做**：连续答对 N 次（默认 2）移出
- 【待定】公式题 / 图片题（理工科大概率需要，但渲染成本高）、间隔重复排程（艾宾浩斯）

### F. 打印与导出（横向能力）

原稿只在日程表里提到"一键生成打印文件"。建议把它当成**横向能力**，而不是某个模块的附属：

- 日程表 → A4 计划表
- 错题本 → 卷子式（题干在前，答案在末页）
- 学习报告 → PDF（周报 / 月报）
- 中文排版细节：字体、页边距、分页、页眉页脚、表格不跨页断裂

### G. 学习统计【新增】

原稿没有，但 A/C/D/E 的数据天然能产出：

- **指标**：专注时长、任务完成率、刷题正确率、连续打卡天数
- **呈现**：日历热力图（类似 GitHub 贡献图）——和"学习日历"是同一个界面的两种表达，性价比很高
- **理由**：这类工具的用户粘性几乎都来自"看得见的积累"

## 四、模块联动矩阵

原稿提到"要和学习日历有联动"，展开成具体数据流：

| 来源 | 去向 | 联动内容 |
|---|---|---|
| 日历 | 全部模块 | 某一天作为聚合容器 |
| 日程 | 事件 | 日程块可一键转为带提醒的事件 |
| 事件 | 日历 | 截止日当天的格子显示标记/红点 |
| 番茄钟 | 事件、统计 | 专注时长归属到具体事件 |
| 刷题 | 日历、统计 | 当天题量 / 正确率标记 |
| 全部 | 打印 | 按当前视图导出 |

## 五、优先级与 MVP 边界

**P0 · 能自己用起来的最小闭环**

1. 本地存储 + 日历月视图 + 备忘条
2. 事件（标题、截止时间）+ App 内提醒 + 提醒方案
3. 日程：手动加时间块 + 周计划表格视图
4. 番茄钟：25/5 固定
5. 刷题：Excel 导入 + 单选 / 判断 + 错题本

**P1**

- 课表导入（含单双周）、日程模板、A4 打印
- 系统级通知、多节点提醒
- 刷题多题型、模拟考试、错题重做

**P2**

- 统计与热力图、错题本打印、云同步与多设备、间隔重复

**路径建议**：先打通「日历 → 事件提醒 → 番茄」这条每天都用的链路，刷题作为独立模块并行开发、后接入。原稿把 5 件事并列，容易平均用力，结果半年都出不来一个能用的版本。

## 七、技术难点（按"会卡住项目"排序）

1. **后台提醒**：程序没开就提醒不了，这是同类 App 的普遍硬伤。三条路线：应用内定时器（简单）→ 系统通知 / 计划任务（中等）→ 服务端推送（重）。
2. **课表导入**：教务系统导出的格式千奇百怪，Excel 结构不固定，解析容易做成无底洞。建议只吃自家模板。
3. **打印排版**：中文字体、A4 边距、表格跨页断行，需要专门调试。
4. **题库导入容错**：多选答案写法、选项分隔符、空行，都要有明确的容错和报错提示。
5. **数据备份**：至少要有"导出 / 导入 JSON 备份"，否则重装系统等于所有记录清零。

## 八、需要你拍板的问题

1. **平台**：Web / Windows 桌面 / 手机 App？——决定提醒能力上限，**最关键的一个**
2. 单机使用，还是多设备同步？
3. 要不要账号体系？
4. 日历"联网"需要哪些数据：节假日 / 农历 / 校历？
5. 课表从哪来：教务系统导出，还是手动填？
6. 刷题的题目有公式和图片吗？主要题型是什么？
7. 提醒只在电脑上，还是要推到手机？
8. 你打算用什么技术栈"纯手搓"？
9. 目标是自己用，还是也给同学用 / 以后上架？
